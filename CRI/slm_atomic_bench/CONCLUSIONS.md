# SLM 原子操作微基准：Intel XPU vs NVIDIA

## 1. 目的

DSA top-k 的 cand kernel 移植自 sglang 的 `topk_bf16_small.cuh`，这个算法每个元素要做两次 SLM 原子加来建直方图。它在 NV 上整个 kernel 不到 6–7 µs（event 计时），移植到 XPU 后却比旧路径还慢（10.5 µs 对 8.3 µs，profiler 只计 kernel）。按阶段拆开测，第 1 轮直方图耗时最多。

我们想知道慢的原因是"Xe 的 SLM 原子吞吐低"，还是"同一地址上的原子冲突"。

## 2. 设备

| XPU | NV |
|---|---|---|
| 型号 | Intel Graphics 0x674f | NVIDIA RTX PRO 5000 72GB Blackwell |
| 计算单元 | 32 个 XeCore | 110 个 SM |

## 3. 方法

- 代码：`xpu.cpp`（SYCL）和 `cuda.cu`（CUDA）的 kernel 逻辑相同，输出格式相同。
- 一个 WG 有 512 个工作项，sub-group / warp 宽度为 32，SLM 16 KB。
- 每个工作项对 SLM 做 N 次操作，地址由"地址模式"决定。相邻两次操作交替访问两块区域，防止编译器把连续的加法合并掉。
- 耗时用设备端 event 计（XPU 用 profiling event，CUDA 用 cudaEvent），先预热 3 次，再取 21 次的中位数。
- 每次操作的成本用斜率算：`(t(N) - t(0)) / N`，N 取 1024。启动、清零、barrier 和写回这些固定开销都在截距里抵消。因此 NV 的 t0 约为 6 µs（cudaEvent 包含启动开销）也不影响结论。
- 指标 `lane-ops/ns/unit`：每个 XeCore 或 SM 每纳秒完成多少个 lane 的操作，越大越好。没有按频率折算。
- 规模：1 个 WG（对应单行延迟的场景），以及每个 XeCore 或 SM 放 4 个 WG（满载吞吐）。

操作类型：

| 模式 | 含义 |
|---|---|
| `atom` | `fetch_add` / `atomicAdd`，不使用返回值 |
| `atom_ret` | `fetch_add` / `atomicAdd`，累加返回值 |
| `plain` | 普通 volatile 读后写回（非原子），作对照 |
| `alu` | 不访问 SLM，只做整数运算 |

地址模式（每个 sub-group 32 个 lane）：

| 模式 | 地址 | 含义 |
|---|---|---|
| `uniq` | `sg*32 + lane` | 所有 lane 地址都不同，无冲突 |
| `k2/k4/k8` | `sg*32 + lane/k` | sub-group 内每 k 个 lane 共用一个地址 |
| `k32` | `sg*32` | 整个 sub-group 共用一个地址 |
| `wg` | `0` | 整个 WG 共用一个地址 |
| `bank` | `lane*32 + sg` | 地址各不相同，但全部落在同一个 bank |
| `xsg` | `lane` | sub-group 内不冲突，16 个 sub-group 共用同样的 32 个字 |

## 5. 结论

1. **没有冲突时，Xe 的 SLM 原子并不慢。** `atom uniq` 下 Xe 单个 WG 为 82.5，NV 为 46.5；满载时 Xe 为 114，NV 为 41。"Xe 的 SLM 原子吞吐低"这个假设不成立。

2. **Xe 不合并同地址的原子，会串行执行；NV 会合并。**
   - NV 的 `atom`（不带返回值）在 uniq、k2…k32 和 wg 之间几乎不变（约 42–46），说明硬件把同地址的原子合并了。
   - Xe 的 `atom` 随共用地址的 lane 数增加而迅速下降：82.5 → 44.9 → 16.8 → 6.7（k8）。
   - 带返回值的原子（`atom_ret`）两边都会随 k 下降，NV 在 k32 时也只有 2.6。所以 NV 的合并只对不使用返回值的原子有效。

3. **Xe 上，不同 sub-group 打同一地址也会串行（`xsg`）。** 即使 sub-group 内部的地址都不同，只要 16 个 sub-group 共用同一组字，Xe 单个 WG 就从 82.5 降到 12.3（约 1/7），满载从 114 降到 33。NV 不受影响（45.0 / 41.5）。

4. **bank 冲突的影响正好相反。** NV 在 `bank` 模式下只有 2.6，下降一个数量级以上；Xe 还有 20 左右，影响不大。所以 NV 原版用 `kNegShift` 错开 bank，在 Xe 上意义不大；Xe 上要避免的是同一地址。

5. **对 DSA top-k 的影响：**
   - `topk_bf16_small` 的直方图用不带返回值的 `atomicAdd`。数据的指数部分往往很集中（rand 数据约 75% 落在同一个高字节 bin），NV 的硬件合并掩盖了这一点。
   - 到了 Xe，这些原子变成在同一地址上串行：只用 1 份直方图时第 1 轮要约 34 µs。
   - 按 lane 复制直方图只能消除 sub-group 内部的冲突，消除不了 sub-group 之间的冲突（`xsg`），还要付出清零和合并的代价。32 份副本时第 1 轮仍要约 2.9 µs，清零加合并另需约 2.5 µs。
   - 移植到 Xe 时，应该在软件里先合并再写 SLM：热点 bin 先在寄存器或 sub-group 内规约计数，每个 sub-group 只做一次原子；剩下比较分散的元素再直接做原子。

## 6. 注意事项

- 两边的数据都没有按频率折算，只适合比较趋势和量级。要按每周期比较，需要分别除以各自的实际频率。
- `plain` 是有依赖的读后写回，主要受访问延迟限制，不代表 SLM 带宽上限。
- `alu` 只用来看循环本身的开销。两边编译器的展开方式不同，数值不宜直接对比。
- 原始数据见 `xpu.log`、`cuda.log`。复现命令：`bash run_xpu.sh`、`bash run_cuda.sh`（NV 上用 `CUDA_VISIBLE_DEVICES` 选卡）。
